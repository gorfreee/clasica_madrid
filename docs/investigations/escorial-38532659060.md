## Cambio conservador

El adapter conserva el calendario original de la API en metadata interna.
Sólo interpreta el reloj técnico de Mahler como fecha sin hora cuando coinciden:
canonical/título, ID de API, postid, enlace TEC, URL/nombre del único schema Event,
fecha de API/visible/schema/microdata, `all_day: true`, inicio exacto 00:00:00 y fin
23:59:59 del mismo día (con el mismo offset en schema y microdata).
La hora visible de esa misma fecha puede completar entonces el calendario.
Un 00:00 explícito y legítimo sigue siendo 00:00; no hay regla global para medianoche.
Un dato estructurado distinto o una API con reloj explícito contradictorio sigue fallando.

Las identidades independientes que contradigan la observación fallan aunque
canonical y h1 coincidan. Las fechas/años y relojes del schema también se contrastan.
El canonical incorrecto sigue reteniendo la ficha y ahora incluye más evidencia:
IDs, schema con sus fechas, calendario de API y horario visible.

La única extensión compartida permite transportar `hydrationDiscrepancies` del
parser a `hydration.discrepancies`, sumándolas al diagnóstico ya existente.
No modifica ninguna prioridad, validador, cobertura ni regla de otras fuentes.
`mergeObserved` no lleva esa metadata a clasificación ni al catálogo.
La recuperación conserva valores originales e interpretación bajo
`resolution: detail-preferred`; las contradicciones conservan `withheld`.
